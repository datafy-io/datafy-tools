    For your security team: exact permissions, the temporary role, and how to verify all of this

    The scan is read-only. It makes no changes to any resource and is safe to run in production. It only lists and describes:

    • ec2:DescribeVolumes, ec2:DescribeInstances, ec2:DescribeRegions, ec2:DescribeImages, ec2:DescribeSnapshots
    • dlm:GetLifecyclePolicies and backup:ListBackupPlans
    • organizations:ListAccounts and sts:AssumeRole, to reach each account in your organization

    With --setup-role it creates a CloudFormation StackSet named DatafyDiscovery holding a minimal read-only role, and always deletes it when the scan finishes — including when it fails. Want to see exactly what it would create first? Run the same command with --print-role-template instead: it prints the template and exits, without contacting AWS or deploying anything.

    This page cannot send anything anywhere. It is a single file with no external scripts or fonts, and it carries a Content-Security-Policy that blocks every network connection — your browser enforces it, and you can check it in the developer tools. You could disconnect from the internet and it would work the same.

    The scanner is open source, so you can read it before running it: github.com/datafy-io/datafy-tools.
